# Redis Console

A full-stack developer console for a custom Redis-compatible server written in Java.

This project combines a Redis-style TCP server with a React frontend and a Spring Boot REST API. The goal is not only to build a usable Redis interface, but to understand how a Redis-compatible system works internally: networking, the RESP protocol, command execution, concurrent clients, in-memory storage, and persistence.

## Architecture

```text
┌──────────────────────────┐
│      React Frontend      │
│   TypeScript + Vite      │
│        :5173              │
└────────────┬─────────────┘
             │ HTTP / REST
             ▼
┌──────────────────────────┐
│    Spring Boot API       │
│        :8080              │
└────────────┬─────────────┘
             │ TCP / RESP
             ▼
┌──────────────────────────┐
│    Custom Java Redis     │
│        :6380              │
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│   In-memory / persistent │
│          storage          │
└──────────────────────────┘
```

The browser does not connect directly to the Redis TCP server. Spring Boot acts as the bridge between the React application and the custom Redis implementation.

## Current Features

### Custom Redis Server

The Redis server implements the core Redis-style request/response flow over TCP and uses RESP-compatible communication.

Current core functionality demonstrated and tested includes:

- TCP server on port `6380`
- RESP request parsing
- `PING`
- `ECHO`
- `SET`
- `GET`
- Missing-key responses
- Multiple client connections
- Shared in-memory key/value storage

The implementation is designed to grow gradually as more Redis concepts are added.

### Web Dashboard

The React dashboard currently includes:

- Dashboard
- Command Console
- Key Explorer
- Server information
- About page
- Dark developer-focused UI
- Smooth page transitions
- Command history
- Interactive key inspection UI
- Connection status indicator

### REST API

The Spring Boot layer exposes REST endpoints that allow the frontend to communicate with the Redis server through a persistent TCP client/session layer.

The current frontend integration uses:

```text
GET  /api/redis/ping
POST /api/redis/connect
POST /api/redis/command
DELETE /api/redis/connect/{sessionId}
```

## Example

A command entered into the web console:

```text
PING
```

travels through the following path:

```text
React Console
      ↓
POST /api/redis/command
      ↓
Spring Boot
      ↓
RedisClient
      ↓
TCP / RESP
      ↓
Custom Java Redis :6380
      ↓
+PONG
```

For stateful commands:

```text
SET test hello
```

followed by:

```text
GET test
```

the value is stored and retrieved from the Redis server rather than generated by the frontend.

## Running the Project

### 1. Start the Redis server

Run the custom Java Redis server with the required arguments.

Example:

```text
--port 6380
```

Additional runtime arguments can be supplied for persistence configuration.

### 2. Start Spring Boot

Run the Spring Boot application on:

```text
http://localhost:8080
```

Verify the API with:

```text
http://localhost:8080/api/redis/ping
```

A successful response currently looks like:

```json
{
  "type": "simple-string",
  "value": "PONG"
}
```

### 3. Start the React frontend

From the dashboard project:

```powershell
npm.cmd run dev
```

The Vite development server runs at:

```text
http://localhost:5173
```

## Testing

The custom Redis server can also be tested directly with `redis-cli`.

Example:

```bash
redis-cli -h <windows-host-ip> -p 6380 PING
```

Basic command tests:

```text
PING
ECHO hello
SET test hello
GET test
```

These should be tested against the custom Java Redis implementation rather than a system-installed Redis server.

## Design Goals

This project is being developed with two goals:

1. Build a working Redis-compatible system from the ground up.
2. Understand and demonstrate the systems concepts behind the implementation.

The dashboard is intentionally separated from the Redis server so that the core database implementation remains independent from the user interface.
